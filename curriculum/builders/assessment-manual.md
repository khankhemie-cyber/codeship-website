# Builders Assessment Manual
**Document ID:** CSA-BLD-AM-EN-v1.0 · **Program:** Builders (Grades 2–3) · Instructor-only volume — contains answer keys.

---

## 1. Assessment philosophy at this level

Grades 2–3 quizzes mix picture items with short written/code-reading items; instructor reads every item aloud. Low-stakes, never ranked. Evidence for rubric criteria may be typed code, handwritten code, spoken explanation, or workbook work (→ CSA-STD-CF §7).

## 3. Diagnostic — "First Voyage" (S1.1, no grade)

- Page-parts sheet: labels heading/paragraph/picture correctly? (concept baseline)
- Typing scan during first `<h1>`: hunt-and-peck / steady / fluent (informs starter-file level)
- Reading comfort with short instructions (informs pairing)
- Prior exposure: "have you seen code before?" (note only)

## 4. Quizzes (5 items, 10 min, read aloud) — with keys

### Q1 — Tag Spotter (S1.3: tags, page parts)
1. Circle the tag that makes the biggest heading: `<p>` / `<h1>` / `<img>`. **Key:** `<h1>`.
2. Draw a line from `<p>` to its partner. Options: `</p>` `<p>` `<h1>`. **Key:** `</p>`.
3. What's wrong with `<h1>Hello`? Circle: nothing / missing closing tag / wrong word. **Key:** missing closing tag.
4. Which tag shows a picture? **Key:** `<img>`.
5. Label the printed mini-page: which part is the heading? Circle it. **Key:** the h1 text.

### Q2 — Skeleton Builder (S1.5: structure)
1. What goes inside `<body>`? Circle: things we SEE / the page's secret name. **Key:** things we see.
2. Where does `<title>` live? **Key:** in the `<head>`.
3. Order the skeleton 1-2-3: body / html / head → **Key:** html, head, body (html wraps first).
4. Circle the correctly nested pair. **Key:** `<body><p>Hi</p></body>` (vs. crossed nesting).
5. Why do we write alt text? Circle: decoration / so everyone can know what the picture shows. **Key:** so everyone can know.

### Q3 — Style Reader (S2.3: CSS, lists)
1. In `h1 { color: red; }` circle the SELECTOR. **Key:** `h1`.
2. What's missing: `h1 { color red }`? **Key:** the colon/semicolon (accept either named).
3. Which list for "steps to feed a fish"? `<ul>` / `<ol>`. **Key:** `<ol>`.
4. Which tag is each list item? **Key:** `<li>`.
5. HTML is the ___, CSS is the ___. Circle pair: structure/style. **Key:** structure & style.

### Q4 — Class Act (S2.5: classes, integration)
1. Circle the class in `<h2 class="snowy">`. **Key:** `snowy`.
2. Which CSS rule styles it? `.snowy {}` / `snowy {}` / `#snowy {}`. **Key:** `.snowy {}` (the dot!).
3. True/false: one class can style many elements. **Key:** true.
4. Match property → what it changes: `color`, `font-size`, `background-color` (3 lines). **Key:** text colour / size / behind-the-text colour.
5. Circle the complete rule. **Key:** `p { color: green; }`.

### Q5 — Link Detective (S3.3: links, multi-page)
1. Which tag makes a link? **Key:** `<a>`.
2. In `<a href="feeding.html">Food</a>`, circle where it GOES. **Key:** `feeding.html`.
3. The link is broken. File is `feeding.html`, href says `feading.html`. Why broken? **Key:** spelling/typo mismatch.
4. Every page needs a way ___. **Key:** home/back.
5. Circle the words the reader clicks. **Key:** Food (the link text).

### Q6 — Guide Writer (S3.5: informational writing)
1. Circle the better instruction: "Food goes in the bowl area" / "1. Put one scoop of food in the bowl." **Key:** the numbered verb-first one.
2. Instructions should start with a ___ (action word/verb). **Key:** verb.
3. Order matters in instructions: which list? **Key:** `<ol>`.
4. Who is a guide written for? Circle: me / the person who needs to use it. **Key:** the user/audience.
5. Fix this step (one action per step): "Feed the fish and clean the tank and check the water." **Key:** any split into separate steps.

### Q7 — Persuasion Power (S4.3: persuasive writing, design)
1. Fact or opinion: "Bees pollinate many food plants." **Key:** fact.
2. Fact or opinion: "Bees are the coolest insects." **Key:** opinion.
3. Circle the call to action: "Bees are nice." / "Plant one flower this spring!" **Key:** plant one flower.
4. Big bold headline text makes it feel: unimportant / important. **Key:** important.
5. A good campaign uses: only opinions / facts AND feelings. **Key:** facts and feelings.

### Q8 — Builder Expert (S4.5: whole-year integration)
1. Write (or circle) the tag pair for a paragraph. **Key:** `<p></p>`.
2. Circle the CSS that makes h1 orange. **Key:** `h1 { color: orange; }`.
3. Link `bees.html` — circle the correct code. **Key:** `<a href="bees.html">Bees</a>`.
4. Before publishing we check: true ☐ kind ☐ safe ☐ — what does "safe" mean here? **Key:** no private info (name/address/school details).
5. Your friend's page shows raw code. First thing to check? **Key:** a missing `>` / broken tag (accept "tag doctor step 1").

## 5. Marking guide

Same thresholds as all programs: 5 secure / 3–4 developing / 0–2 support (1:1 in next Build). Two+ children missing the same item → whole-class re-teach. Scores recorded within 24 h; returned with a named strength, never a ranking.

## 6. Semester project rubric

Program-standard criteria with Builders descriptors:

| Criterion | Emerging | Developing | Proficient | Extending |
|-----------|----------|------------|------------|-----------|
| Concept & creativity | Follows the example closely | Brief with own touches | Own version, clearly theirs (their sections, their words) | Original angle or extra audience thought |
| Technical skill | Tags with heavy support | Semester's tags/CSS with prompts | Semester's skills correct & independent (clean nesting, working rules/links) | Combines beyond the ask (extra classes, pages, styles) |
| Process & problem-solving | Stalls at errors | Fixes with help | Uses tag-doctor/link checklist independently | Debugs others' pages kindly; prevents bugs |
| Communication & sharing | Shows silently | One sentence | Full presentation frame; writing fit for audience | Confident Q&A; writing genuinely usable/persuasive |

**Per-semester technical anchors:** S1 structure & tags · S2 CSS/lists/classes · S3 links/multi-page/instructions · S4 persuasion/design intent.

## 7. Capstone rubric (Community Helper Website)

Anchors: Technical = 2+ correctly linked, styled pages; Concept = a real local helper, child's own celebration of them; Communication = informs AND persuades; Process = launch checklist self-run. Safe-sharing compliance is pass/fail gate (fix before showcase, never publish otherwise).

## 8. Reflection, self- and peer-assessment

Workbook reflection meters + semester reflections; "I like… / I wonder…" oral protocol every project day; S3.5 adds an authentic-audience question; C.2 adds classmate compliments page.

## 9. Certificate criteria

Issue at C.2 when: capstone site has 2+ linked pages with correct tags and deliberate styling AND at least 3 of 4 semester projects completed. Gaps → make-up build time + family conversation first.
