## Semester 1 — Password Strength Checker 🔐
**Opener:** *Python logic can help protect people online.*

| Page | Session | Activities |
|------|---------|------------|
| S1.1 | Hello, Python / Know Your Enemy | Myth vs. fact table on "hacking" (3 rows, before/after class). My first Python lines, handwritten. Traceback I met + what it meant. |
| S1.2 | Strings & Secrets | Weakness anatomy: rank 5 given test-passwords weakest→strongest and justify. String toolbox: `len()` / `in` / `.lower()` with my own examples. |
| S1.3 | Rules of Strength | My 4 rules, written as code AND as "why" sentences. Compound-condition practice: when does `A and B` fire? |
| S1.4 | Functions & Scoring | `strength()` design box: inputs, checks, score math, verdict bands. Full trace of one call, row by row. |
| S1.5 | Launch + Audit ★ | Adversarial log: test-strings that tried to fool my checker + results. **Private safety audit** (folds closed; take home). Reflection: "my strongest rule and why". |

## Semester 2 — Smart Sorting AI 🧠
**Opener:** *AI models learn patterns from data — and inherit the biases in that data.*

| Page | Session | Activities |
|------|---------|------------|
| S2.1 | How Machines Learn | Rules vs. examples: sort 6 everyday AIs, justify each. Our sorter plan: classes, example sources. |
| S2.2 | Train Your First Model | **Training log:** classes / examples per class / 10 predictions (input, prediction, confidence, right?). |
| S2.3 | Trust but Verify | **Evaluation table:** 10 held-back tests → accuracy = right/total = ___%. Per-class notes. "Would I trust it at this % to ___?" |
| S2.4 | The Bias Experiment | **Experiment record:** what we skewed / what broke (evidence) / real-world echo I connected it to / the fix / accuracy before → after. |
| S2.5 | Findings brief ★ | The brief, drafted: trained / tested / broke / fixed / would-never-trust-it-to. Reflection: "the data's blind spots become the model's blind spots — my example." |

## Semester 3 — Chatbot for Good 🤖
**Opener:** *Building AI responsibly means thinking about who it helps and who it might harm.*

| Page | Session | Activities |
|------|---------|------------|
| S3.1 | Bots Among Us | Purpose planner: who it helps / 5 things they'd ask / best answers / bot name + personality. |
| S3.2 | Talk to Me | Loop skeleton, handwritten. My 3 first intents (keyword → response). First "didn't understand" moment logged. |
| S3.3 | Smarter Answers | My intents dictionary (table form). Fallback line, drafted with care. |
| S3.4 | The Responsibility Review | **The checklist, completed:** helps / could harm / data it touches / fails safely / discloses it's a bot — findings + the fix I made. |
| S3.5 | Demo day ★ | User-test log: 5 real questions → hit or fallback. My improvement. Presentation line: "my bot could harm by ___, so I ___." |

## Semester 4 — Data Detective 🔎
**Opener:** *Real data analysis turns raw numbers into insight.*

| Page | Session | Activities |
|------|---------|------------|
| S4.1 | Questions First | **Case file:** dataset chosen / rows & columns sketch / my 3 investigable questions (checked: answerable from these columns?). |
| S4.2 | Compute the Truth | Stats table: column / count / mean / min / max + sanity-check verdict ("plausible because…"). Surprise number logged. |
| S4.3 | Group & Compare | Comparison record: groups / means / difference / my outlier + hypothesis. |
| S4.4 | Show, Don't Tell | Chart sketch with labels. Two headlines: honest vs. clickbait (keep the honest one, learn from the other). My caveat line. |
| S4.5 | Report day ★ | **Insight report frame:** question → evidence (numbers + chart) → insight → caveat. Reflection: "what the numbers did NOT say." |
