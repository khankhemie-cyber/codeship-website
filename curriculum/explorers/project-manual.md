# Explorers Project Manual
**Document ID:** CSA-EXP-PM-EN-v1.0 · **Program:** Explorers (K–Grade 1)

Each semester project follows the standard template (→ CSA-STD-PUB §8). Rubrics live in CSA-EXP-AM-EN §6–7; this volume holds the delivery detail.

---

## Project 1 — My Helpful Robot (Semester 1)

- **Overview:** an interactive scene in which the child's robot character performs a helpful job (waters plants, delivers mail, tidies toys) through an ordered block sequence, started by a trigger.
- **Objectives / outcomes:** sequencing; triggers & events; position & direction; explaining a program aloud.
- **Required skills by build day:** 3+-block sequence (S1.2), directional movement (S1.3), start/tap triggers (S1.4).
- **Materials:** devices with block-coding app; arrow cards; workbook planner p. S1.4.
- **Timeline:** seeded S1.1 (be-the-robot) → planned S1.4 → built & presented S1.5.
- **Teacher guide:** anchor every choice in "who does your robot help?" — the helper framing keeps ideas concrete. Accept any job that can be shown with movement + one trigger. Pre-build a spare robot scene for children returning from absence.
- **Student instructions (read aloud):** "Choose who your robot helps. Build the steps of its job in order. Add a trigger so it starts when we tap. Be ready to tell us: *My robot helps ___ by ___.*"
- **Extensions:** second character reacting; sound effects; robot that speaks.
- **Presentation guide:** partner-pair presentation with the two-sentence frame; presenter taps to start live.
- **Example outcomes:** plant-watering robot (flag-start walk to plant, tap to sprinkle); mail robot visiting two houses; toy-tidy robot pushing a block "toy" to a box.
- **Common challenges:** job too abstract ("helps with feelings") → coach to a showable action; sequence runs before trigger added → revisit S1.4 demo.

## Project 2 — Kindness Cards (Semester 2)

- **Overview:** an interactive digital card for a real person; tapping elements triggers animations, messages, or a recorded kind voice note.
- **Objectives / outcomes:** simple if-then logic; kindness online; digital footprint awareness.
- **Required skills:** tap-trigger if-then (S2.2); recording (S2.3); private-vs-shareable check (S2.4).
- **Materials:** devices with mic access; kind-words anchor chart; footprint sorting cards.
- **Timeline:** planned S2.1 → interaction S2.2 → recording S2.3 → footprint check + finish S2.4 → delivered S2.5.
- **Teacher guide:** the recipient must be real (family, friend, school helper) — authenticity powers the kindness lesson. Run the recording station as a rotation. Before delivery day, verify no card contains private information (full names, addresses).
- **Student instructions:** "Make a card for someone real. When they tap it, something kind should happen. Check: is everything on your card safe to share?"
- **Extensions:** two tappable surprises; a card in another language the child speaks.
- **Presentation guide:** "My card is for ___. When you tap ___, ___ happens." Deliver physically at pickup or send per consent rules.
- **Example outcomes:** grandparent card with tap-to-hear "I love you"; thank-you card for a custodian with growing sunflower; get-well card with giggling teddy.
- **Common challenges:** recording shyness → allow sound-effect alternative; "kind" slipping into "flashy" → return to the recipient: "what would make *them* smile?"

## Project 3 — Recycling Sorter (Semester 3)

- **Overview:** an interactive sorting game where tapping each waste item sends it to its correct bin with feedback — the program "makes good decisions" by rules.
- **Objectives / outcomes:** if-then rules; debugging with the 3-question protocol; environmental decision-making.
- **Required skills:** stating rules as if-then (S3.1); differentiated tap responses (S3.2); bug-hunting (S3.3); systematic testing (S3.4).
- **Materials:** physical sorting objects; sorter starter scene; test checklist card; bug badges.
- **Timeline:** rules S3.1 → 2 items S3.2 → debugged S3.3–S3.4 → demoed S3.5.
- **Teacher guide:** keep the physical-to-digital bridge alive — every digital rule should echo a physical sort the child performed. The planted-bug session (S3.3) is the program's flagship debugging lesson: keep it playful, badge every fix.
- **Student instructions:** "Teach your sorter the rules. Tap every item to test. If something goes wrong — great! Hunt the bug with the 3 questions and fix it."
- **Extensions:** third bin; trick item that explains itself; score-keeping sound.
- **Presentation guide:** live demo + "my favourite bug I fixed was ___."
- **Example outcomes:** 3-item paper/plastic/compost sorter; sorter with "oops, try again!" wrong-bin responses.
- **Common challenges:** identical responses for all items (copy-paste effect) → ask "how does the *banana's* rule differ?"; frustration at own bugs → invoke badge culture ("that's a badge moment!").

## Project 4 — My Neighbourhood Map (Semester 4)

- **Overview:** an interactive map of the child's real world — home, school, park — with a character travelling programmed routes and tappable places that respond.
- **Objectives / outcomes:** position & direction; sequencing; debugging; representing the real world in code.
- **Required skills:** paper-map planning (S4.1); ordered routes (S4.2); place triggers (S4.3); route debugging (S4.4).
- **Materials:** paper/crayons; devices; test checklist; example picture maps.
- **Timeline:** planned S4.1 → routes S4.2 → triggers S4.3 → debugged S4.4 → toured S4.5.
- **Teacher guide:** this is the integration project — quietly check each child touches all three skill families (route = sequencing/direction, taps = events, checklist = debugging). Personal maps carry emotional weight; every map is "correct" if it's *their* world.
- **Student instructions:** "Draw your real places. Program your character's journey between them. Make places do something when tapped. Test the whole journey."
- **Extensions:** second character; voice-label tour; weather layer.
- **Presentation guide:** the guided tour: "Welcome to my neighbourhood! This is ___. Watch when I tap ___."
- **Example outcomes:** home→school→park route with singing birds; map with grandma's house that says hello.
- **Common challenges:** map scope creep (8 places) → limit to 3–4; routes crossing obstacles → debug demo S4.4 covers it.

## Capstone — Show-and-Tell App

- **Overview:** the child designs and builds an app entirely from their own idea, using any skills from the year, and presents it at a family showcase.
- **Objectives / outcomes:** independent application of all program skills; presentation confidence. This delivers the program's headline outcome: *gives a computer clear instructions and builds a simple interactive app.*
- **Requirements:** the idea is the child's own; contains a sequence AND a trigger; presented with the 3-sentence frame.
- **Timeline:** planned + built C.1 → finished, rehearsed, showcased C.2.
- **Teacher guide:** protect idea ownership fiercely — spark cards for the stuck, but never assign. Coach only with questions. Schedule the showcase with families 2 weeks ahead (→ PH §7).
- **Student instructions:** "This one is all yours. Plan it, build it, show it. Your app needs steps in order and a trigger — everything else is your imagination."
- **Presentation guide:** family showcase stations; frame: "My app is… When you tap… I'm proud of…"; certificates follow (AM §9).
- **Example outcomes:** dancing-pets party app; rocket-launch countdown; "my baby sister's giggle button."
- **Common challenges:** idea paralysis → spark cards + "what made you laugh this week?"; overscoping → planner limits to one scene.
